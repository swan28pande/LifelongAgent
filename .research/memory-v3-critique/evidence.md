# Evidence ledger: memory_v3, long context, and stronger memory

Checked 2026-09-29. Evidence below is kept separate from the judgments in [report.md](report.md). Published scores are comparable **within** a paper's stated protocol, not with this repository's saved scores.

| ID | Direct evidence | Limit |
|---|---|---|
| L1 | `memory_v3` uses a fixed extraction pipeline for dated preference, fact, and event rows; raw turns are indexed; a separate summarizer builds week, month, year, and lifetime summaries. One read agent chooses from six read-only tools. [Ingestion](../../memory_v3/ingest.py), [agent](../../memory_v3/agent.py), [tools](../../memory_v3/tools.py), [summarizer](../../memory_v2/summarizer.py) | This describes the implemented system, not its measured accuracy. |
| L2 | The `memories` table stores `content`, `entity`, `type`, `speaker`, and one `source_date`; it has no source-turn identifier, validity interval, or explicit correction link. [Schema](../../memory_v2/store.py#L55) | Raw dialogue remains available through date and semantic retrieval. |
| L3 | The summarizer asks an LLM to select recurring entities, then asks LLMs for weekly, monthly, and yearly patterns. It caches selected entities per summarizer instance. [Summarizer](../../memory_v2/summarizer.py#L658) | There is no separate deterministic verification of a proposed periodic rule in this path. |
| L4 | The archived synthetic run used `gemini-3.1-flash-lite`, one user, 60 days, and 67 questions. Its LLM judge marked 32/67 correct (0.478), including 0/3 direct pattern-identification questions. [Saved results](../../results/synthetic/v3/qa_results.json), [summary](../../results/synthetic/v3/README.md) | Three pattern questions are too few for a general conclusion; this archive predates the current default model. |
| L5 | The saved LoCoMo run covers one dialogue (conv-26), 199 questions. v3 agentic scored 0.460 token F1 overall / 0.557 excluding adversarial; one-pass reading of the same v3 store scored 0.608 / 0.546. Agentic reading used about eight LLM calls and 30 seconds per question versus one call and 4.4 seconds. [Local comparison](../../results/locomo/README.md) | The answer prompts differ. Adversarial scoring rewards particular abstention phrases; the one-pass and Mem0 context budgets also differ. The single dialogue cannot establish broad ranking. |
| L6 | Raw turn text totals 169,247 characters / 30,805 whitespace-separated words for the local synthetic history and 58,108 characters / 10,428 words for LoCoMo conv-26. Computed from [synthetic conversations](../../datasets/eval/conversations.json) and [LoCoMo dialogue](../../baselines/locomo/data/locomo10.json). | Rough token estimates depend on the model tokenizer and prompt formatting. No full-history baseline appears among the saved runs. |
| P1 | Mem0 paper, LoCoMo, same answer-model setup: full context 72.90% LLM-judge with 26,031 memory tokens; Mem0 66.88%, Mem0g 68.44%, best tuned dense RAG 60.97%. Full context p95 response time 17.117 s versus Mem0 1.440 s. [Mem0, Table 2](https://arxiv.org/pdf/2504.19413) | The paper's LoCoMo protocol and judge differ from this repository's scores. Its full-context cost includes a roughly 26k-token prompt. |
| P2 | LongMemEval-S supplied roughly 115k-token histories: GPT-4o full history 0.606 versus 0.870 with only gold evidence sessions. [LongMemEval, Figure 3b](https://arxiv.org/pdf/2410.10813) | Gold-session retrieval is an oracle upper bound, and the evaluated GPT-4o was a 2024 model. |
| P3 | LongMemEval-M: adding extracted facts to a raw-round retrieval key raised top-10 recall 0.692→0.784 and answer accuracy 0.670→0.720. [LongMemEval, Table 3](https://arxiv.org/pdf/2410.10813) | This isolates one indexing improvement; it does not benchmark `memory_v3`. |
| P4 | Google reported that Gemini 2.5 Flash retrieves simple factoids accurately regardless of their position, even near the context limit. [Retrieval Quality at Context Limit](https://research.google/pubs/retrieval-quality-at-context-limit/) | This is simple factoid retrieval, not evolving personal-state or multi-session reasoning. |
| P5 | APEX-MEM's LoCoMo non-adversarial table: full-context GPT-4o 87.52% versus APEX-MEM GPT-4o reader 86.75%. Its LongMemEval table with Claude 4.5 Sonnet reader: APEX-MEM 86.2%, fact-augmented search 72.5%, full context 62.2%. [APEX-MEM, Tables 1 and 4](https://aclanthology.org/2026.acl-long.749.pdf) | The two benchmarks differ; answer models are matched within the cited rows, but APEX construction uses separate models and up to 40 read tool calls. The paper's cost tables give inconsistent total-token figures. |
| P6 | TiMem's evaluated adaptive hierarchy achieved 76.88% on LongMemEval-S versus 68.68% for MemOS with the same answer model; high-level layers without detailed lower-level records scored 64.20%. [TiMem, Tables 2 and 4](https://aclanthology.org/2026.findings-acl.1091.pdf) | Its hierarchy is distinct from v3's. Its paper reports added consolidation calls. |
| P7 | In Mem0's ablation, the graph raised overall LoCoMo judge score 66.88→68.44, helped temporal answers, and reduced single-hop and multi-hop scores. [Mem0, Tables 1–2](https://arxiv.org/pdf/2504.19413) | Adding graph structure has task-dependent effects; this does not measure v3. |
| P8 | APEX-MEM has source-linked evidence, canonical entities, validity intervals, hybrid search, and graph/SQL tools that v3 does not. [APEX-MEM, §§3–4](https://aclanthology.org/2026.acl-long.749.pdf) | A more expressive architecture is not automatically a higher-scoring one on periodic-choice prediction. |
| P9 | A March 2026 preprint compared full-history GPT-5-mini with a flat Mem0 pipeline using GPT-5-nano for extraction and GPT-5-mini for answers. Its judge gave full context 92.85% versus 57.68% on LoCoMo, and 82.40% versus 49.00% on LongMemEval. [Pollertlam and Kornsuwannawit, Table 3](https://arxiv.org/pdf/2603.04814) | This is a preprint; GPT-5-mini also served as judge. It compares one flat memory implementation, not v3 or a strong temporal graph. It uses a different evaluation protocol from APEX-MEM. |
| P10 | Model dates differ from paper dates: LongMemEval's 2024–25 full-context result used GPT-4o; Mem0's April 2025 experiment used GPT-4o-mini; TiMem was published July 2026 but primarily used `gpt-4o-mini-2024-07-18`; APEX-MEM was published July 2026 and tested GPT-5 and Claude 4.5 Sonnet readers. [LongMemEval](https://arxiv.org/abs/2410.10813), [Mem0](https://arxiv.org/abs/2504.19413), [TiMem](https://aclanthology.org/2026.findings-acl.1091/), [APEX-MEM](https://aclanthology.org/2026.acl-long.749/) | Recent publication alone does not mean a frontier model was evaluated. APEX-MEM's full-context LoCoMo baseline did not use GPT-5. |

## Open empirical questions

1. How would full-history reading perform on the 60-day synthetic task and all 10 LoCoMo dialogues with the **same** reader and scoring protocol?
2. How much do v3's structured dated rows, period summaries, and tool loop each add beyond tuned raw-turn retrieval?
3. Can any method infer a recurring-choice rule and predict a future choice reliably across held-out users, schedules, deliberate exceptions, corrections, and insufficient-evidence cases?
4. How does a current frontier full-context reader compare with v3 and a strong memory system on the *same* histories, prompt, and judge?
